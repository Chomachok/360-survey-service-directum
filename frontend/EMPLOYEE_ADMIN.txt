

Обновление фронта зафиксированы следующие изменения 
- /employees — список карточек с ФИО, email, редактированием и удалением.
- /employees/new — добавление сотрудника.
- /employees/{id}/edit — обновление карточки.
- /employees/{id}/delete — отдельная страница подтверждения удаления.
- /import — существующая страница ручного добавления и импорта CSV сохранена.
- Формы проверяют ФИО и формат email. Список обновляется через React Query.
- Для сохранения и удаления клиент вызывает PUT и DELETE. Если сервер отвечает
  404 или 405, пользователь увидит уведомление об отсутствующем backend API.

ЧТО НУЖНО ДОБАВИТЬ В BACKEND 
Сейчас EmployeesController предоставляет GET /api/employees,
POST /api/employees и POST /api/employees/import. Для обновления и удаления
серверу нужны ещё два обработчика:

1. PUT /api/employees/{id}
   - принять JSON с полями fullName и email;
   - проверить входные данные и найти сотрудника по id;
   - сохранить изменения в постоянном хранилище;
   - вернуть обновлённый объект сотрудника (id, fullName, email);
   - вернуть 404, если сотрудник не найден, и понятную ошибку валидации,
     если данные некорректны.

2. DELETE /api/employees/{id}
   - найти сотрудника по id и удалить его из постоянного хранилища;
   - вернуть успешный статус (например, 204 No Content);
   - вернуть 404, если сотрудник не найден.

Оба маршрута должны использовать ту же авторизацию, что и остальные маршруты
админки. После их добавления фронтенд сможет отправлять операции на сервер;
до этого редактирование и удаление не меняют данные.
